## Code findings and changes

1. Native SDL polled only `scePadReadState`. A short press between polls could be missed. The patched driver uses `scePadRead` with 64 samples, 120-byte stride and timestamp offset 0x50 (compile-time ABI assertions). This matches the local PS5_RetroArch reference's input ABI. Replay samples chronologically, retain live state on an empty batch, and fall back to the previous reader on batch errors. Hotplug detection remains separate. Patch: `patches/ps5/sdl-buffered-input.patch`.
2. SDL2Input previously discarded controller events and read only final state. A DOWN/UP pair in one drain disappeared. In menu repeat mode (`getRepeatDelay() > 0`) retain mapped button-down bits for the matching controller and apply directional rotation. This does not change gameplay's latest-state consumer. Multiple taps of the same button within one drain coalesce; analog flicks and trigger axes are not latched by this change.
3. Correct the driver's hat construction to use all currently held directions, not only changed directions; an unrelated button change must not clear a held D-pad hat.
4. A weak timing probe wraps the frontend frame, input poll, input callback, and swap. Every >=5 seconds it reports averages/maxima plus the maximum input-poll gap, for at most 12 reports; subsequent probe calls immediately return. It preserves errno. No per-input disk writes. Build marker: `input-r8-20261002`.

These establish two plausible lost-input mechanisms, not proof that they account for all console latency. `INPUT_PERF` will distinguish long sampling gaps, menu callback stalls, and presentation time. It is not an end-to-end physical input latency measurement.
