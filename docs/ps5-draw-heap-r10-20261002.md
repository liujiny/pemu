## Change A: batch-eligible UI geometry

The linked native runtime already enables PS5_MULTIDRAW_BATCH and PS5_DEFERRED_DRAW_BATCH. Its archive SHA256 matches the currently built native runtime (30b72dffa06c2b2a8b1a4144aef869d748e6d855745852a5cdc2b5f186d0dc2c). Ordinary deferred eligibility accepts triangle lists, not general strips/fans. Existing Shape fill and outline geometry uses fan and strip respectively. Ineligible draws drain the pending batch and follow the synchronous path.

On PS5 only, VertexArray::update expands strips/fans to triangle lists for VBO upload. CPU logical vertices, bounds and public topology remain unchanged. GLRenderer selects GL_TRIANGLES with the matching expanded count. setPrimitiveType reuploads when the topology changes. No class layout changes; other platforms retain their original path. Primitive order, alternating strip winding, last provoking vertices, degenerate triangles and full vertex attributes are preserved. Expansion occurs when geometry is uploaded, not each idle frame. Allocation/upload size increases for fan/strip geometry, traded against fewer driver batch interruptions. Eligibility has other conditions; the real speedup requires hardware measurement.

No SDK/GPU runtime synchronization, shader, resource-retention or batch limits changed. No rendering quality setting changed. This retains the existing OpenGL baseline and does not implement Vulkan.

## Change B: application heap budget and evidence

A pEMU-owned copy of the existing native-app allocator is staged by native-build-pfbneo.sh. It changes the heap to 512 MiB and retains allocation routing, foreign-pointer ownership, initialization and realloc semantics. It preserves the upstream license. The installed SDK and reference project are untouched.

HEAP ready confirms initialization; bounded manual stack formatting records up to four allocation failures with requested bytes. The existing bounded performance reports now include heap capacity, live usable bytes, peak and failure count. These are owned CPU-heap counters, not total process or GPU memory. A mapping failure retains the previous libc fallback and emits a message. Increasing capacity does not fix leaks, all OOM paths, tracking-slot exhaustion or unidentified memory corruption.

FBNeo core source is unchanged. The detected unchecked Konami allocation remains in upstream core code: if allocation still fails, the log should identify that and the game may still crash. Do not report all-game launch success until tested.
