## Static findings

- EPIC12 uses thready.h; PS5 matches neither Windows nor pthread platform selectors,
  so r20 invokes gfx_exec synchronously from SH3 device handlers. Thread Blitter On
  did not create a worker. Thus prior cpu_us included software blitting; draw_us
  measured final screen extraction, not all sprite work. Low sync_us did not prove
  a cheap blitter. This is a confirmed code path, not proof that it explains every dip.
- Salvia's ordered snapshot/worker design is applicable. Commands/source uploads are
  copied before submission; every new submission drains the previous job. PS5 now
  uses a dedicated SDL mutex/condition worker only in epic12.cpp, not rewind.
- gfx_create_shadow_copy and gfx_exec share m_clip. Existing pre-submit wait protects
  it. Added drain before bitmap presentation, scan, reset and driver teardown. The
  clipping margin setter avoids even identical writes while a worker could read it.
- Worker does not access SH3 CPU, timer or IRQ state. Emulated blitter busy timing is
  still set by the main thread. Save layout contains no host worker metadata; r20
  state buffers and temporary-file replacement are unchanged.
- CPU interpretation remains serial. Xbox PowerPC DRC source-validation/cache/native
  blocks cannot be transplanted into an x86-64 interpreter. r19 portable blend work
  remains; no opcode, CPU clock or speedhack semantics changed in this iteration.
- Future thread scheduling/PS5 condition-variable behavior and actual gains require
  console testing. Heavy SH3-only work will not become parallel through this change.
